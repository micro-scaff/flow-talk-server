# 前端对接文档

本文面向后续生成或重构前端项目使用，目标是让前端按同一套接口、类型和实时协议接入 `flow-talk-server`。

完整 HTTP 接口以 [openapi.json](./openapi.json) 为准；本文重点补充前端实现时需要的页面数据流、状态管理和 WebSocket 接入规则。

## 基础配置

### 服务地址

本地开发默认后端地址：

```text
http://127.0.0.1:8080
```

WebSocket 地址由 HTTP 地址转换得到：

```text
ws://127.0.0.1:8080/api/ws?token={jwt}&device_id={device_id}
```

推荐前端使用环境变量：

```text
VITE_API_BASE_URL=http://127.0.0.1:8080
```

如果使用其它框架，变量名可按框架约定调整，但建议统一封装为 `API_BASE_URL`。

### 通用响应格式

HTTP 接口统一返回：

```json
{
  "code": 200,
  "data": {},
  "message": "操作成功"
}
```

前端封装请求时建议：

- `code === 200`：返回 `data`
- `code !== 200`：抛出带 `message` 的业务错误
- HTTP `401`：清理本地登录态并跳转登录页
- HTTP `500`：展示通用错误文案，并查看后端日志定位原因

### 鉴权

登录或注册成功后，后端返回：

```json
{
  "user": {
    "id": 1,
    "username": "alice",
    "nickname": "Alice",
    "auth_source": "local",
    "status": 1
  },
  "token": "<jwt-token>"
}
```

前端需要保存：

- `token`：HTTP `Authorization` 和 WebSocket 建连使用
- `user`：当前用户基础信息
- `device_id`：浏览器本地生成并持久化，例如 `web-{uuid}`

HTTP 鉴权头：

```text
Authorization: Bearer <jwt-token>
```

WebSocket 鉴权参数：

```text
/api/ws?token=<jwt-token>&device_id=<device_id>
```

## 推荐前端模块

建议生成前端项目时拆成以下模块：

```text
src/
  api/                 HTTP API 封装
  hooks/
    useWebSocket.ts    WebSocket 建连、心跳、发送事件
  pages/
    LoginPage.tsx
    ChatPage.tsx
  stores/              登录态、会话、消息、在线状态
  types/               接口 DTO 和 WebSocket 事件类型
  utils/
    session.ts
    device.ts
    clientMessageId.ts
```

如果使用 React，可以用 `useState/useReducer` 或 Zustand 管理状态；如果使用 Vue，可以用 Pinia。

## 核心类型

### User

```ts
interface User {
  id: number;
  username: string;
  nickname?: string;
  avatar_url?: string;
  auth_source?: string;
  status: number;
}
```

### Conversation

```ts
interface Conversation {
  id: number;
  type: "direct" | "group" | string;
  direct_key?: string;
  title?: string;
  avatar_url?: string;
  owner_id?: number;
  member_count?: number;
  last_message_id?: number;
  last_message_at?: string;
  last_message?: Message;
  unread_count?: number;
  members?: ConversationMember[];
}
```

### Message

```ts
interface Message {
  id: number;
  conversation_id: number;
  sender_id: number;
  client_msg_id?: string;
  message_type?: "text" | "image" | "video" | "file" | string;
  content?: {
    text?: string;
    url?: string;
    name?: string;
    size?: number;
    [key: string]: unknown;
  };
  status?: "sending" | "normal" | "recalled" | "deleted" | string;
  sent_at?: string;
}
```

本地临时消息可以额外使用前端字段：

```ts
interface LocalMessage extends Message {
  local_status?: "sending" | "failed";
}
```

不要把前端临时字段提交给后端。

## HTTP 接口接入

### 认证

```text
POST /api/auth/register
POST /api/auth/login
POST /api/auth/external
GET  /api/me
```

前端启动时建议：

1. 从本地读取 `token` 和 `user`。
2. 有 token 时调用 `GET /api/me` 校验登录态。
3. 校验失败时清理登录态并跳转登录页。

### 会话

```text
GET  /api/conversations
GET  /api/conversations/{conversation_id}
POST /api/conversations/direct
POST /api/conversations/groups
```

单聊创建请求：

```json
{
  "target_user_id": 2
}
```

群聊创建请求：

```json
{
  "title": "项目群",
  "avatar_url": "",
  "member_ids": [2, 3]
}
```

前端点击用户发起单聊时：

1. 调用 `POST /api/conversations/direct`。
2. 使用返回的 `conversation.id` 进入会话页。
3. 刷新会话列表。

### 历史消息

```text
GET /api/conversations/{conversation_id}/messages?before_id={message_id}&limit=20
```

首次进入会话：

1. 调用会话详情接口。
2. 调用消息列表接口，`limit` 建议 20 或 50。
3. 按 `id` 升序渲染消息。

上拉加载更多：

1. 取当前最早消息 `id` 作为 `before_id`。
2. 拉取更早消息。
3. 合并时按 `id` 去重。

### HTTP 发送消息

```text
POST /api/conversations/{conversation_id}/messages
```

该接口只作为调试、脚本发送、WebSocket 不可用时的降级路径。聊天页面发送消息首选 WebSocket `message.send`。

降级发送时必须复用同一个 `client_msg_id`：

```json
{
  "client_msg_id": "web-uuid-001",
  "message_type": "text",
  "content": {
    "text": "hello"
  }
}
```

## WebSocket 接入

### 建连

```text
GET /api/ws?token={jwt}&device_id={device_id}
```

前端建议在登录态确认后立即建立 WebSocket。断线后可以重连，但要避免多个页面重复创建多条连接；如果允许多标签页同时在线，也需要确保每个标签页有独立连接或统一由 BroadcastChannel 协调。

### 事件信封

所有 WebSocket 消息使用统一 JSON：

```json
{
  "type": "event.name",
  "request_id": "req-001",
  "payload": {}
}
```

字段说明：

- `type`：事件类型
- `request_id`：客户端生成，请求类事件建议必填
- `payload`：事件数据

### 心跳

客户端定时发送：

```json
{
  "type": "ping",
  "request_id": "ping-001"
}
```

服务端返回：

```json
{
  "type": "pong",
  "request_id": "ping-001",
  "payload": {
    "server_time": "2026-07-02T12:00:00+08:00"
  }
}
```

建议前端每 25 到 30 秒发送一次 `ping`。如果连续多次没有收到 `pong` 或连接进入 `closed/error`，进入重连流程。

### 发送消息

聊天页面发送消息必须优先使用 WebSocket：

```json
{
  "type": "message.send",
  "request_id": "req-001",
  "payload": {
    "conversation_id": 1,
    "client_msg_id": "web-uuid-001",
    "message_type": "text",
    "content": {
      "text": "hello"
    }
  }
}
```

前端发送流程：

1. 生成 `client_msg_id`。
2. 在当前会话插入本地 `sending` 消息。
3. WebSocket 已连接时发送 `message.send`。
4. 不要同时调用 HTTP 发送接口。
5. 等待 `message.ack`。
6. 超时或 WebSocket 不可用时，使用同一个 `client_msg_id` 调用 HTTP 发送接口降级。

### message.ack

服务端收到 `message.send` 并成功入库后，向发送连接返回：

```json
{
  "type": "message.ack",
  "request_id": "req-001",
  "payload": {
    "id": 1001,
    "conversation_id": 1,
    "sender_id": 2,
    "client_msg_id": "web-uuid-001",
    "message_type": "text",
    "content": {
      "text": "hello"
    },
    "status": "normal",
    "sent_at": "2026-07-02T12:00:00+08:00"
  }
}
```

前端处理：

1. 用 `payload.client_msg_id` 找到本地 `sending` 消息。
2. 替换为服务端返回的正式消息。
3. 如果找不到本地消息，按 `id` 去重后追加。
4. 刷新会话列表中的最后消息。

### message.deliver

服务端向会话 active 成员的在线连接广播：

```json
{
  "type": "message.deliver",
  "payload": {
    "id": 1001,
    "conversation_id": 1,
    "sender_id": 2,
    "client_msg_id": "web-uuid-001",
    "message_type": "text",
    "content": {
      "text": "hello"
    },
    "status": "normal",
    "sent_at": "2026-07-02T12:00:00+08:00"
  }
}
```

前端处理：

1. 按 `payload.id` 去重。
2. 如果 `payload.conversation_id` 是当前会话，追加到消息列表。
3. 如果不是当前会话，只更新会话列表的最后消息和未读数。
4. 如果收到的是自己发送的消息，也按 `id/client_msg_id` 去重，避免 ack 和 deliver 重复展示。

### error

发送失败时，服务端返回：

```json
{
  "type": "error",
  "request_id": "req-001",
  "payload": {
    "message": "参数校验失败"
  }
}
```

前端处理：

1. 找到对应 `request_id` 或 `client_msg_id` 的本地消息。
2. 标记为 `failed`。
3. 提供重试入口。

## 聊天页面数据流

### 初始化

1. 校验登录态。
2. 获取当前用户 `GET /api/me`。
3. 获取用户列表 `GET /api/admin/users`。
4. 获取会话列表 `GET /api/conversations`。
5. 建立 WebSocket。
6. 如果路由中带 `conversation_id`，加载会话详情和历史消息。

### 选择会话

1. 设置当前 `conversation_id`。
2. 拉取会话详情。
3. 拉取历史消息。
4. 调用已读接口更新会话已读游标。

已读接口：

```text
POST /api/conversations/{conversation_id}/read
```

请求体：

```json
{
  "last_read_message_id": 1001
}
```

### 发送文本消息

1. 校验当前会话存在。
2. 校验输入文本去空格后非空。
3. 构造 `client_msg_id`。
4. 本地追加 `sending` 消息。
5. WebSocket 发送 `message.send`。
6. 收到 `message.ack` 后替换本地消息。
7. 收到 `message.deliver` 后按 `id` 去重。

### 离线补偿

用户重新进入页面或 WebSocket 重连后：

1. 刷新会话列表。
2. 对未读会话展示 `unread_count`。
3. 用户进入会话时拉取历史消息。
4. 历史消息和实时消息按 `id` 去重合并。

## 在线状态

接口：

```text
GET  /api/users/{user_id}/presence
POST /api/users/presence/batch
```

批量查询请求：

```json
{
  "user_ids": [1, 2, 3]
}
```

前端建议：

- 会话列表或成员列表加载后批量查询在线状态
- WebSocket 连接状态只表示“当前用户是否连上服务端”
- presence 接口表示“目标用户是否在线”

## 资源消息

上传接口：

```text
POST /api/resources/upload
```

上传成功后返回资源 URL。资源上传接口不会自动发送消息；前端需要再通过 WebSocket `message.send` 发送图片、视频或文件消息。

图片消息示例：

```json
{
  "type": "message.send",
  "request_id": "req-image-001",
  "payload": {
    "conversation_id": 1,
    "client_msg_id": "web-image-001",
    "message_type": "image",
    "content": {
      "url": "/api/static/uploads/image.png"
    }
  }
}
```

## 前端生成检查清单

生成前端项目时，至少实现：

- 登录、注册、退出
- token 持久化和 `GET /api/me` 校验
- HTTP client 统一处理 `code/data/message`
- WebSocket 建连、心跳、重连和关闭
- WebSocket `message.send`
- `message.ack` 替换本地发送中消息
- `message.deliver` 实时追加和去重
- HTTP 发送消息降级逻辑
- 会话列表、单聊创建、群聊创建
- 会话详情、历史消息分页
- 当前会话已读上报
- 在线状态批量查询
- 上传资源后通过 WebSocket 发送资源消息

## 常见问题

### 为什么发送方看到了消息，接收方没及时看到？

优先检查前端是否仍在只调用 HTTP 发送接口。聊天页面应该使用 WebSocket `message.send`。HTTP 发送接口只作为降级路径。

### 为什么消息重复出现？

通常是同时调用了 WebSocket `message.send` 和 HTTP 发送接口，或者没有按 `id/client_msg_id` 去重。一次用户发送操作只应走一条发送路径。

### WebSocket 断开后怎么办？

前端应展示连接状态，并启动重连。重连期间发送消息可以先保留在本地 `sending` 状态；超时后再使用同一个 `client_msg_id` 走 HTTP 降级发送。
